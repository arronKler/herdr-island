Known issues.

Read this first: Island is a front end for Herdr, not a full Herdr client, and it never auto-approves blocked agents. Use Herdr for full workspaces, tabs, splits, and menus. Keep permission, trust, and usage dialogs in the terminal.

01 / TerminalIt connects only to the current pane

The interactive terminal supports only Herdr 0.9.5's single-pane protocol 22

Limit

Other protocol versions fail with an explicit incompatibility message. After upgrading or downgrading Herdr, the deck, delivery, and jumps still work, but the detail terminal may not connect. Use Herdr / Ghostty for the full terminal.

Settings → Environment shows the version; the error names the protocol mismatch.

The detail view is not a full Herdr client

Limit

Workspaces, tabs, splits, menus, and client-level shortcuts are not part of the detail view. The earlier full client, the separate 1080 × 720 terminal window, and its proxy were withdrawn. What remains is the single-pane terminal inside the 660 × 640 detail. Click "Open in Herdr" for the full interface.

Some terminal capabilities are still missing

Limit

The full key-down/repeat/key-up protocol, focus reporting, OSC 52 clipboard, and in-terminal image display are still incomplete. Keyboard, IME input, paste, mouse reporting, Shift-drag selection, scrollback, and size sync are supported.

Source: docs/terminal-verification-2026-11-10.md

Protocol 22's mouse channel has no acknowledgement

Known

Keyboard, text, and paste wait for the socket API to acknowledge. Mouse, scroll, and resize do not have equivalent acknowledgement. Strict global ordering across channels is not guaranteed; under mixed input, some programs may observe a different order.

Clipboard, bell, and title events may be incomplete

Limit

Herdr 0.9.5 sends these events to the global foreground client. A direct single-pane attachment is not that client, and clipboard events also lack a source pane identifier. Copying to the system clipboard, bells, or title updates inside the terminal may therefore not appear. Local ⌘C / ⌘V still works.

Input is not replayed after a disconnect

Known

Reconnect manually after the connection drops; keystrokes already typed are not resent automatically. Input sent before the drop may already have run. Check the terminal before reconnecting. If another client holds the pane, you can take it over explicitly.

02 / Window & permissionsCapture and context are optional

Window lock supports only the current Space and display

Limit

The lock targets a specific windowID. Closing and reopening a window changes the ID, so it must be locked again. Minimizing or switching Spaces hides the tether and makes capture fail. A lock exists only for the current run.

DRM or secure windows may capture as black

Limit

ScreenCaptureKit cannot bypass protected content. When capture fails, delivery degrades to text, context, and files, and keeps the task you typed.

Window lock is unavailable without a notch

Limit

Island appears as a menu-bar item. ⌃⌥H, ⌃⌥N, the deck, details, and delivery still work. The droplet only lives on displays with a notch, and window lock is unavailable without one.

Fields go missing without Screen Recording / Accessibility

Known

Without Screen Recording: no screenshot is attached; text, automatic context, and files still send. Without Accessibility: selected text, page URL, and document path are not read; screenshots, text, and files still send. Neither blocks delivery, but the prompt has less content.

The capture call has no separate cancel button

Known

If a permission dialog or ScreenCaptureKit hangs, one send may wait a long time. Closing the composer does not abort a capture already in progress. If it never returns, check for a system permission dialog first.

Automatic context is best-effort

Known

Selected text, page URL, and document path come from the target app's Accessibility attributes. If the app does not expose them, times out, or returns nothing, those fields are empty. The caps are 4,000, 2,048, and 1,024 characters. Island does not capture the screen or read the clipboard to fill the gap.

03 / Delivery & new tasksQueueing, attachments, and the main agent

The main agent is identified by pane + workspace + kind

Known

Herdr may reuse a pane ID for another workspace or agent. Only a match on pane, workspace, and kind counts as the same agent. Otherwise Island says "The main agent exited; this delivery will start a new one" instead of sending to the wrong target.

Only one message can be queued while busy

Known

While the main agent is running you can queue one message. It is delivered when the turn ends, provided the interactive terminal for that pane is not open. Sending another while one is queued is refused. Blocked or unknown-state agents cannot receive messages; handle them in the terminal first.

Attachments are absolute paths, not copied files

Known

At most 8; ~/ is expanded. Island checks readability before sending and blocks the send if a file is missing. Queued messages are checked again before delivery and missing files are dropped. Only absolute paths are supported.

Pasted images have size and retention limits

Known

Up to 16 MB and 40 megapixels per image. Images become local PNGs with a 0700 directory and 0600 files. Images older than 7 days are cleaned the next time the terminal opens or an image is pasted; cleanup is not scheduled while the app is closed.

A failed new task may leave a workspace behind

Limit

Creation has three stages: prepare the directory, start the model, then submit and confirm. If a later stage fails, the workspace already created is retained and the error includes its pane ID. Island does not retry creation or resend automatically. When an existing pane or an uncertain outcome is involved, inspect the terminal first, then retry or start a separate task.

Multi-line first tasks wait up to 20 seconds for an empty input box

Known

Multi-line Claude, Codex, and Cursor tasks confirm that a real empty input box is ready before the first send, preserving line breaks and indentation. If the input area cannot be identified or already has content, Island checks for up to 20 seconds and then exits safely, leaving the terminal for inspection without appending Return or resending the task.

Trust, usage, and model pickers are yours to handle

Limit

Cursor's workspace-trust dialog and Codex's usage/model picker are never confirmed automatically. Automatic messages check for these dialogs before sending and refuse if one is present; no keys are simulated. New-task worktrees also do not pass --trust-repository.

04 / Install & updatesNot notarized, but updates are signed

Ad-hoc signing means the first launch needs manual approval

Limit

The app is not notarized by Apple, so Gatekeeper does not show an identified developer. Click "Open Anyway" in System Settings → Privacy & Security as described in the install steps, or remove the quarantine flag. Do not disable Gatekeeper globally.

Updates may ask for system permissions again

Known

An ad-hoc identity can change between builds, so macOS may treat the new version as a different app and ask again for Automation, Screen Recording, or Accessibility. Check Settings → Permissions after each update. A stable Developer ID signature and notarization would avoid it; neither exists today.

Prereleases are manual downloads

Limit

Stable releases update automatically. The feed uses releases/latest, which excludes prereleases, so beta builds must be downloaded by hand.

The updater's only requests are the appcast fetch and the signed archive download from GitHub. It sends no account, identifier, prompt, or usage data.

05 / Unverified & tradeoffsThese are not hidden bugs

Retina sharpness with mixed display scaling is not fully measured

Unverified

One panel can still span multiple displays, and the drop canvas covers the union of all screens. Per-display sharpness at different backing scales has not been fully verified. The known issue is layout coordinates, not window splitting.

The full-desktop drop panel swallows clicks outside the composer

Tradeoff

While the drop surface is open it covers the desktop, and a click outside the composer is received by the modal layer first (usually to dismiss it) instead of reaching the app below. This is a deliberate quick-capture tradeoff, not ordinary floating-window behavior.

The app UI is currently Chinese-only

Known

There is no localization framework or English app UI. The site is available in English and Chinese, but the in-app copy is Chinese.

Deliberate boundaries: no auto-approving blocked agents; no sending y / Enter for you; no full Herdr client inside the detail; the menu-bar icon does not change color with status; no whole-screen capture; no uploading prompts, code, or screenshots; no accounts, cloud sync, team rooms, or general notch utilities. These are product choices, not pending bugs.

06 / ReportingInclude these details

File an issue on GitHub Issues. Please include:

  • Island version and build (Settings → Environment).
  • macOS version, Apple Silicon / Intel, and whether the Mac has a notch.
  • Herdr version, any protocol message, and the executable and socket paths (Settings → Environment).
  • Reproduction steps: where it first went wrong, and whether you switched Spaces, windows, or agents beforehand.
  • Relevant logs. You can launch with --log <path> and reproduce.
  • If it involves sending: whether Screen Recording / Accessibility / Automation are granted, and the notice text you saw.

Do not paste: terminal output containing tokens, private code, or full window screenshots. Keep only what a minimal reproduction needs; redact sensitive content in screenshots.

For a field-by-field account of what Island reads, writes, and keeps local, see What it reads. To remove everything, see Uninstall.

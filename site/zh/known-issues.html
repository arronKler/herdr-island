先读这一句：Island 是 Herdr 的前端，不是完整 Herdr 客户端，也不会自动批准 blocked。完整工作区、标签、分屏和菜单请用 Herdr；需要你确认的权限、信任和用量弹窗请留在终端处理。

01 / 终端它只连接当前 pane

交互终端只适配 Herdr 0.9.5 的单 pane 协议 22

限制

其他协议版本会明确提示不兼容。升级或降级 Herdr 后，任务台、投递和跳转仍然可用，但详情终端可能无法连接；完整终端请用 Herdr / Ghostty。

设置 → 运行环境可查看版本；错误提示会写明协议不匹配。

详情不是完整 Herdr 客户端

限制

工作区、标签、分屏、菜单和客户端级快捷键不属于详情视图。此前加入的完整客户端、独立 1080 × 720 终端窗口和对应代理已撤回；现在只保留 660 × 640 详情里的单 pane 终端。需要完整界面点「在 Herdr 打开」。

部分终端能力还没有接入

限制

完整的按键按下/重复/释放协议、焦点报告、OSC 52 剪贴板、终端内图像显示仍需补齐。当前支持键盘、中文输入、粘贴、鼠标报告、Shift + 拖动选择、滚轮历史和尺寸同步。

依据：docs/terminal-verification-2026-11-10.md

协议 22 的鼠标通道没有处理确认

已知

键盘、文字和粘贴会等待 socket API 确认；鼠标、滚动和尺寸通道没有同等确认。鼠标与键盘跨通道的严格全序不保证，混合操作时个别程序可能看到顺序差异。

剪贴板、铃声和标题事件可能不完整

限制

Herdr 0.9.5 把这些事件发往全局前台客户端；直接 attach 的单 pane 连接不是那个客户端，剪贴板事件也缺少来源 pane 标识。因此终端内复制到系统剪贴板、响铃或标题更新可能不出现。用 ⌘C / ⌘V 走本地剪贴板仍然可用。

断线不会自动重发输入

已知

连接断开后需要手动重连，已输入的按键不会自动重发；断开前已经发出的输入可能已经执行。重连前先检查终端。另一个客户端占用时可以显式接管。

02 / 窗口与权限截图和上下文都是可选的

窗口锁定只支持当前 Space、当前屏幕

限制

锁定的是具体 windowID；窗口关闭再打开会换 ID，需要重新锁定。最小化或切到别的 Space 时连线隐藏，截图会失败。锁定只存在于本次运行期间。

DRM 或安全窗口可能只能截到黑屏

限制

ScreenCaptureKit 对受保护内容无法绕过。截图失败时投递会降级为文字、上下文和文件，不会丢掉已输入的任务。

没有屏幕凹口时窗口锁定不可用

限制

岛会以菜单栏形态出现，⌃⌥H、⌃⌥N、任务台、详情和投递照常可用；水滴只在有屏幕凹口的屏幕上常驻，窗口锁定在没有屏幕凹口时暂不可用。

屏幕录制 / 辅助功能未授权时字段会缺失

已知

没有屏幕录制：不附截图，仍发送文字、自动上下文和文件。没有辅助功能：不读取选中文本、网页地址和文档路径，截图、文字和文件照常发送。两者都不阻断投递，但 prompt 会少内容。

截图调用没有单独的取消按钮

已知

权限弹窗或 ScreenCaptureKit 卡住时，一次发送可能等待较久。关闭投递框不会中止已经开始的截图调用；如果长时间没有返回，先检查系统权限弹窗。

自动上下文是 best-effort

已知

选中文本、网页地址和文档路径来自目标 App 的辅助功能属性；目标 App 不暴露、超时或返回空时，这些字段就为空。上限分别是 4,000 字符、2,048 字符和 1,024 字符。Island 不会为了补全上下文去截屏或读剪贴板。

03 / 投递与新任务排队、附件和主 agent

主 agent 是按 pane + workspace + kind 识别的

已知

Herdr 可能把 pane ID 复用到另一个 workspace 或 agent；只有 pane、workspace 和 kind 都匹配才算同一个 agent。否则会提示「主 Agent 已退出，这次将新建」，不会把消息发给错误对象。

忙碌时只保留一条排队消息

已知

主 agent 正在运行时可以排队一条，本轮结束且没有打开该 pane 的交互终端时自动投递；已有排队时再发会被拒绝。blocked 或状态未知的 agent 不能接收消息，需要先在终端处理。

附件只传绝对路径，不复制文件

已知

最多 8 个；~/ 会展开。发送前检查文件仍可读，缺失会阻止发送；排队消息投递前会再次检查，缺失的文件会被移除。只支持绝对路径。

粘贴图片有大小和保留限制

已知

单张最多 16 MB、4000 万像素；图片转成本地 PNG，目录 0700、文件 0600。超过 7 天的图片在下次打开终端或粘贴时清理，不承诺 app 关闭期间定时删除。

新任务失败时 workspace 可能保留

限制

创建分「准备目录、启动模型、提交并确认」三步。失败时已经创建的 workspace 会保留，错误里带 pane ID；Island 不会自动重试创建，也不会重复发送。已有 pane 或结果不确定时，先去终端检查，再决定重试或「另建任务」。

多行首条任务最多等待 20 秒确认空输入框

已知

多行 Claude、Codex、Cursor 任务会在首次发送前确认真实空输入框就绪，原样保留换行和缩进。无法识别输入区或已有内容时，最多检查 20 秒后安全退出，保留终端供检查，不补回车或重复发送任务。

信任、用量和模型选择弹窗必须由你处理

限制

Cursor 的工作区信任弹窗、Codex 的用量/模型选择弹窗不会被自动确认。自动消息发送前会检查这些弹窗；检测到就拒绝发送，不会模拟按键。新任务的 worktree 也不会带 --trust-repository。

04 / 安装与升级没有公证，但更新有签名

ad-hoc 签名，首次打开需要手动放行

限制

应用没有经过 Apple 公证，Gatekeeper 不会显示「已识别的开发者」。按安装步骤在系统设置 → 隐私与安全性里点「仍要打开」，或移除 quarantine 标记。不要全局关闭 Gatekeeper。

更新后可能重新询问系统权限

已知

ad-hoc 签名的身份可能随构建变化，macOS 会把新版本当成不同 app，重新询问自动化、屏幕录制或辅助功能。每次更新后检查设置 → 权限。稳定的 Developer ID 签名和公证可以避免；当前没有。

prerelease 需要手动下载

限制

稳定版本会自动更新。feed 使用 releases/latest，不包含 prerelease，所以 beta 版本需要手动下载。

更新器只向 GitHub 请求 appcast 并下载签名更新包，不上传账号、标识、prompt 或使用数据。

05 / 未验证与取舍这些不是隐藏的 bug

多屏混合缩放下的 Retina 清晰度没有完整实测

未验证

一个面板仍可能跨多个 display，drop 画布覆盖所有屏幕的并集；不同 backing scale 的逐屏清晰度没有完整验证。已知问题是布局坐标，不是窗口分裂。

全桌面 drop 面板会吞掉 composer 外的点击

取舍

drop 打开时面板覆盖整个桌面，点击面板外会先被模态层接收（通常用于关闭），不会传给下面的 app。这是 quick-capture 的有意取舍；不是普通悬浮窗行为。

界面文案目前只有中文

已知

没有本地化框架或英文界面。站点已有中英文版本，但 app 内文案是中文。

有意为之的边界：不自动批准 blocked；不代发 y / Enter；不把完整 Herdr 客户端塞进详情；菜单栏图标不随状态变色；不截整个屏幕；不上传 prompt、代码或截图；不做账号、云同步、团队房间或通用凹口工具。这些是产品选择，不是待修 bug。

06 / 报告问题带上这些信息会更快

到 GitHub Issues 提交。请附上：

  • Island 版本和 build（设置 → 运行环境）。
  • macOS 版本、Apple Silicon / Intel、是否有屏幕凹口。
  • Herdr 版本、协议提示、可执行文件和 socket 路径（设置 → 运行环境）。
  • 复现步骤：哪一步开始不对，之前是否切换过 Space、窗口或 agent。
  • 相关日志。可以用 --log <path> 启动并复现。
  • 如果涉及发送：是否授权屏幕录制 / 辅助功能 / 自动化，以及当时的 notice 文案。

不要贴：包含 token、私有代码或完整窗口截图的终端输出。只保留最小复现所需的部分；截图里出现敏感内容时先打码。

需要逐项对照“它读了什么、写了什么、哪些会离开本机”，见它读了什么；需要完全移除，见卸载。
